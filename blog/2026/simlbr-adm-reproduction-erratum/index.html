做论文时的一次基线排查：SimLBR ADM 勘误记录

最近在推进自己的一项 AI 生成图像检测研究，围绕自己的方法想法做对照实验，并整理成论文。比较自己的方案与已有工作时，需要先把对照基线的实现、数据和评测结果核对清楚，SimLBR 是其中一项。

10 月 29 日早上，之前反馈给 SimLBR 作者的一个基线评测问题收到了回复。困扰了一段时间的结果偏差，终于有了具体解释：ADM 的生成图片使用大写 .PNG 后缀，原来的特征提取流程只匹配 *.png，漏掉了全部 6,000 张生成图片。

作者已经在 README 中发布勘误，并表示将更新 arXiv。这篇记录的是自己论文研究中的这次基线排查。自己的方法和完整实验，留待论文中展开。

对照实验里，一个始终对不上的子集

SimLBR 是一项 AI 生成图像检测工作：使用冻结的 DINOv3 提取图像特征，再训练轻量分类头，并在特征空间加入 latent blending 正则。GenImage 实验使用 Stable Diffusion 1.4 数据训练，再观察模型对其他生成器的泛化表现。

我在昇腾 910B 上验证这项对照基线时，大部分子集的结果处在相近区间，ADM 却始终比较低：论文里约为 97%，我的结果约为 70%。

查阅仓库时，我发现这并非一个全新的现象。makabakallllll 已经在更早的 issue #1 中报告过类似偏差，使用 RTX 4090 得到了约 72% 的 ADM 准确率。在这条问题报告上，我补充了另一条环境和实现路径下的独立复现与排查记录。

两个结果接近，值得继续检查，但还不足以直接判断问题来自哪里。换了硬件、使用了特征缓存、预训练权重的获取路径也有差别，每一项都有可能引入偏差。

先检查自己的实验

我先把能核对的环节拆开，整理进了 issue #2。

先核对权重与模型加载。 当时公开权重下载遇到了访问限制，我使用了社区镜像，因此检查了文件哈希、两个镜像的字节一致性，以及加载时是否存在缺失或多余参数。这些检查帮助排除文件不一致和模型结构不匹配，不能替代官方完整校验值提供的来源证明。

再检查特征缓存。 冻结 backbone 后，缓存特征可以减少重复计算，但也多了一条需要验证的路径。我抽取 200 张 ADM 图片，对照缓存特征和即时提取特征，余弦相似度均值约为 0.999964。差异很小，使缓存成为主要偏差来源的可能性降低。

最后核对训练与评测路径。 包括分类头、混合样本与标签、优化器、损失、图像预处理，以及训练参数。复现采用 SD v1.4 的完整训练划分，并在报告中保留了环境和配置，方便作者对照。

这里记录的是当时基线验证留下的证据，本次写作没有重新训练模型。

比单个总准确率更有帮助的，是把两类图片分开看。我的 ADM 结果是：

指标 基线复现结果
总准确率 69.91%
真实图片准确率 97.27%
生成图片准确率 42.55%

真实图片的结果仍然很高，明显的下降集中在生成图片一侧。这个拆分让问题描述具体了许多：作者可以沿着类别、数据路径和评测样本去检查，而不必只面对一个“差了二十多个百分点”的数字。

作者找到了漏掉的 6,000 张图片

北京时间 10 月 29 日 07:33，作者 Aayush Dhakal（adhakal224）在 issue 中回复，表示已经检查并确认 ADM 存在评测错误。

README 的勘误给出了更具体的原因：ADM 生成图片使用 .PNG，而原特征提取代码只匹配小写的 *.png。结果是，评测流程跳过了全部 6,000 张生成图片，却继续计算出了一个看起来正常的准确率。

这个高准确率对应的实际问题变成了：模型在剩下的真实图片上，判断正确了多少。

README 勘误同时列出了发布版 genimage 模型的更正结果：

记录 ADM 准确率 结果的含义
README 中的原发布模型结果 97.0% 只统计了真实图片
作者更正后的发布模型结果 69.4% 纳入此前漏掉的生成图片
我的基线复现 69.91% 我训练得到的 checkpoint，在完整真假图片上评测

后两项落在接近区间，为此前的偏差提供了解释。它们分别是我的独立训练结果和作者发布模型的结果，应按各自来源记录。

一个也需要纠正的小细节：早先两个 issue 将论文数值写成了 96.68%；本次重新核对 arXiv v1 表 1，实际为 96.98%。本文按论文原表记录，并将其与 README 中发布模型的 97.0% 分开说明。

按作者的公开说明，其他 GenImage 子集和 AIGCDetectionBenchMark 结果不受影响；ADM 没有参与训练，发布模型本身不变。GenImage 八子集平均准确率随更正更新为 91.1%。截至本文整理时，README 勘误已经发布，arXiv 提交历史仍只有 v1，论文更新是作者接下来的安排。

以后会更早检查什么

这次让我记住的是：一个指标正常输出，并不代表预期的样本都参加了评测。

文件匹配、预处理、特征缓存、预测和指标汇总之间，每一步都可能改变实际参与统计的样本集合。如果只保存最后一行 accuracy，这些变化很容易被藏起来。

以后做类似实验，我会把几项检查放得更靠前：

  • 按子集和类别记录预期数量、实际加载数量，以及跳过的文件。
  • 保存样本清单，让图片、特征、标签与预测能够逐项对应。
  • 同时查看真实图片和生成图片的分组指标，保留用于汇总的计数。
  • 遇到结果偏差时，先提供可以核对的配置、日志和小范围对照，再讨论原因。

也感谢早先报告问题的复现者，以及作者愿意继续排查并公开更正。在这次上游问题反馈中，我补充了独立复现和审计证据，具体的文件后缀问题由作者最终定位。几份记录连接起来，才让这次讨论有了一个可以核对的结果。

这次基线核对是自己论文实验的一部分。它帮助我更准确地理解对照结果，也让研究过程中的一份排查记录，对上游工作有了一点用处。自己的想法还在继续打磨，这算是其中一个值得记下的小插曲。
